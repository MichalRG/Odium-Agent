# Nest Setup

This skill sets up the **home install** of the AI Nest. The Nest is installed once, in `~/.ai-nest`. Each repository is registered there and gets a project folder, `~/.ai-nest/projects/<name>/`, with its checks, runs and sessions. The repository gets no file and nothing to commit. Only `.git/info/exclude`, which Git never commits, hides `.ai-nest/` (request files) and build output in that clone.

`~/.ai-nest/nest.config.json` is the policy for all projects (models, limits, safety). A top-level section in a project's `nest.config.json` replaces the same section of the policy for that project.

Never commit, push or change repository files during setup, unless the user asks.

## Steps

1. **Install or update.** If `~/.ai-nest/ai_nest/cli.py` does not exist, or the user asks for an update, run `install.py --home` from the odium-agent checkout: `python <checkout>/install.py --home`. In the checkout itself, that is `python install.py --home`. In another folder, ask the user where the checkout is. An update replaces the Nest code and the personal skills. It keeps `~/.ai-nest/nest.config.json`, `~/.ai-nest/.claude/settings.json` and the project folders.
2. **Find the repository.** Run `git rev-parse --show-toplevel` in the folder that the user means. If it is not a Git repository, or it has no commit, stop and tell the user: the Nest needs a Git repository with at least one commit.
3. **Own install.** If the repository root has `nest.config.json`, the repository has its own Nest install (committed or `--local`), and runs use it first. Tell the user, and ask whether to keep it or to remove it for the home install. To remove it, list these files: the paths with status `installed` in `ai_nest/installation.json`, `ai_nest/`, `nest.config.json`, `AI_NEST_README.md`, and the "AI Engineering Nest" sections that the installer added to `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md`. Show the list and remove the files only when the user agrees. For a committed install, the removal is a commit, which the user must approve. For a local install, also remove the block between the `AI Nest local install` lines in `.git/info/exclude`.
4. **Register.** Run `python ~/.ai-nest/install.py --home <repository root>`. Add `--template NAME[:FOLDER]`, once for each stack, when the user names the stacks or when the output says that no checks were found. The output names the project folder and the checks. A second registration keeps the checks that are there; with `--template` it replaces them.
5. **Checks.** Read `<project folder>/nest.config.json` and the repository's own build files: `package.json` scripts, `pyproject.toml`, the CI workflow and the README. Show the checks to the user: name, command, folder and suite. Propose a change where a check does not match how the repository builds and tests, for example when the repository has its own lint script. Each check needs `name`, `argv` (a list), `cwd` (relative to the repository root) and a `suite`: smoke, static, unit, integration, contract, e2e, security or build. One check must have the suite `unit`, because the Nest runs it to see the new tests fail (RED). Put commands that a fresh worktree needs before the checks, for example `npm ci`, in `setup_commands`. Change the file only when the user agrees.
   Ask the user whether they have documents about the project that are not in the repository (architecture, domain, decisions, notes). Copy the ones that they name to `<repository root>/.ai-nest/docs/`, which Git ignores. The explorer reads them before it investigates the code. Without them, it investigates the repository on its own.
6. **Check it.** From the repository root, run `python ~/.ai-nest/ai_nest/cli.py doctor --provider <provider>` (codex, claude or copilot). Then, with the user's authorization, because it runs the repository's code on this machine, run `python ~/.ai-nest/ai_nest/cli.py verify --allow-host-execution`. Report each `NOT READY` line and each failed check exactly. A check that fails on the clean repository blocks every run: fix the check, or tell the user to fix the code, before the first feature.
7. **Permission prompts.** Tell the user that Codex runs the Nest commands outside its sandbox, because they write Git worktrees. At the first prompt, the user can answer "don't ask again" for commands that start with `python ~/.ai-nest/ai_nest/cli.py`.
8. **Done.** Tell the user to start a new chat in the repository and use `/build-feature <request>` in Claude Code or `$build-feature <request>` in Codex. The personal skills are in `~/.claude/skills` (Claude Code) and `~/.agents/skills` (Codex, Copilot).
